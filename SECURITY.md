# Безопасность

ProxyPanel управляет процессами от вашего имени и позволяет менять их команды через
редактор конфига. По сути это **удалённое выполнение кода для того, у кого есть доступ к
панели**. Поэтому:

- **Только loopback.** Панель слушает только `127.0.0.1`/`localhost`/`::1`, другие значения
  `panel.listen` отклоняются. Открывать её в сеть (проброс порта, reverse proxy) не нужно.
- **Защита от сайтов в браузере.** Проверяется заголовок `Host` (DNS rebinding); каждый
  запрос к `/api/` требует заголовок `X-PP: 1` (CSRF: чужой сайт не может его отправить без
  CORS, а CORS выключен); WebSocket логов проверяет `Origin`.
- **Команды — только из `proxies.yaml`.** Произвольные команды из интерфейса не принимаются;
  значения, которые попадают в unit-файлы и конфиги (`description`, параметры `obfuscator`,
  ярлыки), проверяются на переводы строк.
- **Секреты.** Каталог `~/main/.config/proxypanel` и `run/` создаются с правами `700`, файлы
  с ключами — `600` (сразу при создании, без промежуточного `644`).
- **Бинарники.** Скачиваются только из перечисленных в `COMPONENTS` репозиториев GitHub,
  проверяются по sha256 (из GitHub API или `checksums.txt`/`hashes.txt`) и пробно запускаются
  перед заменой. У wg-obfuscator контрольных сумм нет — об этом показывается предупреждение.

Нашли уязвимость — пожалуйста, сообщите через приватный
[security advisory](../../security/advisories/new) репозитория, а не публичный issue.
